# CI 与仓库方案

状态：分层方案为提案；文档阶段的 CI 与 Dependabot 已启用；当前配置见，见 [仓库配置](REPOSITORY-SETUP.md)。

## 1. 仓库组织

建议一个公开单仓库存放内核、CLI、文档、虚构示例和无凭据测试。私有节点、个人订阅与签名材料放在代码仓库外；私有测试配置不通过“以后删掉”处理。许可证已按 D03 选定 AGPL-3.0-only；D02 已接受 GitHub 公开单仓库。

公开仓库使用标准 GitHub-hosted runner 的 Actions 计算用量按当前 GitHub 文档免费；larger runner、存储和其他服务需分别核对。私有仓库按账户当前额度和费率估算，不能把公开仓库的规则直接套用。[GitHub Actions 计费说明](https://docs.github.com/en/actions/concepts/billing-and-usage)；[runner 价格](https://docs.github.com/en/billing/reference/actions-runner-pricing)。正式配置前复核，本文不锁定价格或额度。

## 2. 分层执行

| 触发 | 检查 | 成本与覆盖边界 |
| --- | --- | --- |
| 仅文档 PR | 链接、文档结构、必要的敏感信息检查 | 不启动完整平台矩阵 |
| 普通代码 PR | Linux 格式 / 静态检查、单元、可控集成、依赖检查；macOS arm64 构建与短时烟测 | Linux 测试不替代首发平台运行验证 |
| 数据路径或生命周期 PR | 增加相关竞争检测、断连回收与解析器测试 | 工具按最终语言选择 |
| macOS 接入 PR | macOS 构建；受控实机的路由、DNS、权限与恢复测试 | 无权限的 hosted runner 不计作 TUN 验证通过 |
| 合并至 main | 完整核心集成、相关平台构建 | 同一提交已有有效结果时避免无意义重复 |
| 每周或手动 | 长时间运行、模糊测试、依赖复查和性能趋势 | M0 后再决定是否启用定时工作流 |
| 发布标签 | 声明支持的平台验证、互通、产物、校验和、依赖清单、签名步骤 | 失败时不提升为正式版本 |

macOS TUN 和休眠唤醒需要受控实机环境。可以使用用户设备手动验收或隔离专用 runner，但不能在日常主力机上自动运行不可信 PR 的特权代码。

## 3. 运行约束

- 同一 PR 新提交取消旧运行，发布作业例外；每个 job 设超时与最大矩阵规模。
- 缓存按 OS、架构、工具链及锁文件区分；不缓存凭据，不信任来自不可信 PR 的发布缓存。
- PR 产物短期保留，正式发布产物按版本保留；初始建议 PR 7 天、常规诊断 14 天。
- 第三方 Actions 固定完整提交 SHA，权限默认只读；发布写权限仅赋予对应作业。
- Fork PR 不访问 secrets，不使用带有 secrets 的高权限事件执行 PR 提供的脚本。
- 平台相关测试可按路径缩减，但路径规则变化和共享核心依赖变化仍触发首发平台检查。
- 必需检查始终产生结果；文档专用变更在聚合检查中明确成功，避免路径过滤导致检查永久等待。

## 4. 成本验证

M0 记录冷 / 热缓存耗时和失败率；连续一周后调整层级。先减少重复和无关作业，再考虑付费 runner。初期付费计算预算建议为零，任何调整按用户授权执行。
