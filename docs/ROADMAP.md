## 2. 首版可用的定义

使用虚构示例配置可以完成配置校验、前台启动、状态查看与正常停止；真实节点通过本地私有配置提供。浏览器通过显式代理按域名 / CIDR 选择 DIRECT、REJECT 或远端出站。错误可以定位，密码不会进入日志，退出后不遗留监听和活跃任务。

v0.1 的“可用”限定为已测试的 TCP 显式代理场景；TUN、UDP、全局 DNS 接管和完整 Mihomo YAML 兼容属于后续里程碑。

### 3.1 第一个代码切片：SOCKS5 / HTTP CONNECT → DIRECT

状态：`done`（已在 M1 落地并通过 Tier 1–4 端到端测试）。所属：M0 验证原型，同时作为 M1 的第一条数据链路。

范围：
- 入站：SOCKS5 无认证 CONNECT，支持 IPv4、IPv6、域名三种地址类型；HTTP CONNECT。
- 出站：仅 DIRECT。目标域名交由系统解析器解析（参见架构 §4 中对 v0.1 DNS 的说明）。
- 启动方式：只用 CLI 参数，不读取配置文件，不做规则求值。
- 端口：默认一个 mixed 端口 `127.0.0.1:18484`，按首字节区分协议，`0x05` 为 SOCKS5，其余按 HTTP 处理；可用 `--socks` / `--http` 另外指定独立端口。截至 2026-11-08，18484 在 IANA 注册表中属于未分配段 18464–18515；刻意避开 7890 / 7891 等常见代理工具的默认端口。

默认值（均可通过 CLI 覆盖）：
- 只绑定 loopback；绑定非 loopback 地址时需要显式传 `--allow-lan`。
- 握手超时 10s，出站连接超时 10s，双向空闲超时 300s。
- 并发连接上限 1024，超出时拒绝新连接并记录日志。
- SIGINT / SIGTERM：立即停止 accept，给现有连接最多 5s 排空，然后强制关闭；退出码反映是否干净退出。
- 日志只记录目标主机与端口，不记录载荷。

不在范围内：配置文件与 schema（YAC-005）、规则、REJECT、SOCKS5 认证与出站、普通 HTTP 代理（非 CONNECT 请求转发）、UDP、修改系统代理。

验收：
- 用本地 echo 服务做集成测试，覆盖 SOCKS5 三种地址类型、HTTP CONNECT、半关闭、握手超时、非法请求、并发上限和优雅退出。
- 用 curl 的 `--socks5-hostname` 与 `-x` 手动验证，并照实记录命令和结果；浏览器验证同样如实记录。
- 退出后不遗留监听与活跃任务。
- 记录一次 RSS / 吞吐基线，写明版本、硬件、负载和测量方法；只作基线，不下性能结论。
- `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test` 在本地通过；CI 增加 Linux + macOS 的这三项检查。
- 引入的依赖逐项记录版本、许可证和用途。

交付：在本地分支 `feat/m1-direct-slice` 上提交，不推送远端；不改动未跟踪的 `.agents/`。

## 4. 质量与性能验收

基准固定三组：空闲；200 条空闲 / 低流量 TCP 连接；200 条活动连接及可重复流量。另测短连接风暴与反复重载。记录客户端和服务端配置、连接建立速率、带宽、日志等级、采样周期、RSS 峰值及回落趋势，不能只报单点内存。

M2 的 8 小时与 M3 的 24 小时属于初始稳定性门槛，不等于生产级可靠性证明。M0 定义容忍范围：内存、任务数与文件描述符在预热后应围绕负载波动，结束后回落到可解释范围；发现稳定增长必须定位，不能靠重启掩盖。

性能硬指标在有基线后填写：200 连接 RSS 上限、吞吐损失、p95 延迟增量、重载耗时、恢复时限。没有基线时保留空缺，不能把愿望写成实测。

## 5. 主要风险与调整条件

| 风险 | 提前验证 | 影响与处理 |
| --- | --- | --- |
| macOS TUN 权限 / 分发不成立 | M0 原型和官方要求核查 | 延后 v0.2，先稳定显式代理 |
| 协议库许可不适配 | 引入前检查 | 更换依赖或调整许可证，不能先复制后补手续 |
| DNS 递归与代理回环 | DNS 策略独立集成测试 | 阻断 TUN 合入，先修正出站路径 |
| 用户时间与模型配额不足 | 每周比较可验收产出 | 缩减并行功能，保持里程碑闭环 |
| 兼容需求失控 | 固定字段及协议矩阵 | 未支持能力显式报错，按实际配置新增 |
