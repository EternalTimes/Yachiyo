## 2. ADR-001：语言与运行时

状态：proposed；负责人：项目维护者；目标：M0 结束前接受、修改或拒绝。

背景：项目需要协议生态、稳定转发、macOS 适配和后续跨平台。当前为单人配合 AI 开发，应同时衡量维护成本与可验证的性能。

候选：Go；Rust。工作建议是 Go 作为首个原型语言，先减少跨语言边界；这是一项工程取舍提案，不能据此宣称 Go 必然更省内存或更快。

实验：两个原型实现等价 TCP 转发、取消和半关闭；固定硬件及负载，记录实现时间、依赖、RSS、吞吐、CPU 与泄漏检查。调查所需协议和 TUN 栈的版本、平台与许可证。无需为了比较先实现完整代理内核。

选择条件：能够完成首发协议与平台接入，资源趋势稳定，维护和测试成本可承受。若 Go 的资源基线未达目标或关键依赖不可用，重新评估 Rust；若差异不足以抵消双语言成本，保持单语言。

接受后补充：具体工具链版本、模块布局、构建与测试命令、依赖策略、反方代价及复核条件。工具链选仍在安全支持期的稳定版本；版本号在实施时查证。[Go 安全支持说明](https://go.dev/doc/security/)。

## 3. ADR-002：衍生版本保持开放源码

状态：accepted；日期：2026-10-31。

依据：用户在比较 GPL / AGPL 后明确表示：“我更希望如果未来有衍生品，大家都能保持开放代码”。选择 GNU AGPL version 3；具体版本写法采用 AGPL-3.0-only，避免未经再次决策即授权改用未知的未来版本。

范围：项目原创代码、配置示例与配套文档；单独声明的第三方内容继续按原许可处理。当前没有已引入的代码依赖，兼容性审查随依赖引入进行。

取舍：覆盖分发衍生作品和修改后提供远程网络交互的源码提供义务，允许商业使用；闭源嵌入受覆盖程序的空间更小。不能由此保证所有外围程序都受 AGPL 覆盖，也不要求私人自用的修改一律公开。详见 [LICENSING.md](LICENSING.md)。

实施：根目录保留完整 LICENSE；后续源码标记 SPDX；发布提供与产物匹配的对应源码；设计适合代理用户的源码获取入口。第三方代码、GPLv3 组合以及独立程序边界按实际许可和组合方式审查。

复核：新增核心依赖、改变打包边界或未来考虑另行授权时复核全部权利来源，不能只修改根目录 LICENSE 就替他人贡献或第三方代码改换许可。
