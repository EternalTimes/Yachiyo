## 2. ADR-001：语言与运行时

状态：accepted；日期：2026-11-08；负责人：项目维护者。

背景：项目需要协议生态、稳定转发、macOS 适配和后续跨平台。当前为单人配合 AI 开发，应同时衡量维护成本与可验证的性能。

候选：Go；Rust。初稿建议以 Go 作为首个原型语言，并以 Go / Rust 对照实验决定。

决定：采用 Rust，单语言实现。依据为用户在 2026-11-08 的选择：直接选 Rust，第一个功能就是 Rust 版「SOCKS5 / HTTP CONNECT → DIRECT」，实测只用于验证，不用于对比。原计划的 Go / Rust 对照实验取消，YAC-002 改为 Rust 验证原型。

已知代价：
- 没有对照数据，不能据此宣称 Rust 比 Go 更省内存、更快或开发更快；后续性能结论只描述 Rust 实现本身的实测结果。
- 初稿以 Go 为首选的理由（协议生态、迭代速度、减少跨语言边界）没有经过实验否定；该决定是在缺少对照证据的情况下作出的取舍。
- 用户态 TCP/IP 栈、协议实现等关键依赖的可用性尚未核查（YAC-003），可能需要自行补齐更多实现。

复核条件：出现以下任一情况时重新评估，并在本节记录证据：
1. YAC-003 / YAC-004 发现 TUN 路线或首发协议所需的关键 Rust 依赖不可用、维护停滞，或许可证与 AGPL-3.0-only 不兼容，且自行实现的代价不可接受。
2. M2 / M3 的资源或稳定性门槛因语言或运行时原因无法达到。
3. 维护和测试成本明显超出单人配合 AI 的承受范围。

工具链与布局（第一个切片实施时落地并验证，以下为已确定方向）：
- 使用 stable 工具链，以 `rust-toolchain.toml` 固定具体版本。Rust 安全修复只针对最新 stable，固定的版本需要随之升级；具体版本号在实施时查证。本机 2026-11-08 观察到 Homebrew 安装的 rustc 1.99.1（aarch64-apple-darwin），这不代表最终固定的版本。[Rust 安全政策](https://www.rust-lang.org/policies/security)。
- 采用 Cargo workspace：`crates/yachiyo-core`（连接契约、转发、出站），`crates/yachiyo-inbound`（SOCKS5 / HTTP CONNECT 入站），`yachiyo-cli`（二进制入口）。core 不依赖任何入站协议实现。
- 候选直接依赖：tokio（异步运行时）、clap（CLI 参数）、tracing（日志）、thiserror（库错误类型）、anyhow（仅限 CLI）。引入时逐项记录版本、许可证与用途，并核对与 AGPL-3.0-only 的组合关系，不以本列表代替审查。
- 构建与检查命令为 `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test`，在第一个切片中验证后写入 CONTRIBUTING 与 CI。

## 3. ADR-002：衍生版本保持开放源码

状态：accepted；日期：2026-10-31。

依据：用户在比较 GPL / AGPL 后明确表示：“我更希望如果未来有衍生品，大家都能保持开放代码”。选择 GNU AGPL version 3；具体版本写法采用 AGPL-3.0-only，避免未经再次决策即授权改用未知的未来版本。

范围：项目原创代码、配置示例与配套文档；单独声明的第三方内容继续按原许可处理。当前没有已引入的代码依赖，兼容性审查随依赖引入进行。

取舍：覆盖分发衍生作品和修改后提供远程网络交互的源码提供义务，允许商业使用；闭源嵌入受覆盖程序的空间更小。不能由此保证所有外围程序都受 AGPL 覆盖，也不要求私人自用的修改一律公开。详见 [LICENSING.md](LICENSING.md)。

实施：根目录保留完整 LICENSE；后续源码标记 SPDX；发布提供与产物匹配的对应源码；设计适合代理用户的源码获取入口。第三方代码、GPLv3 组合以及独立程序边界按实际许可和组合方式审查。

复核：新增核心依赖、改变打包边界或未来考虑另行授权时复核全部权利来源，不能只修改根目录 LICENSE 就替他人贡献或第三方代码改换许可。
