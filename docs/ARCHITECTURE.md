# 架构草案

状态：提案。语言尚未定案；建议先以 Go 验证 M0 原型，Rust 作为对照方案。M0 通过 ADR-001 决定后，才落地模块和工具链。

## 1. 模块与依赖方向

采用单仓库、模块化单体。按职责划分逻辑边界，避免为每个接口建立包或引入独立服务。

| 模块 | 责任 | 约束 |
| --- | --- | --- |
| CLI / controller | 校验、启动、停止、状态、受控管理操作 | 不直接实现协议和规则匹配 |
| config | 解析、迁移、校验，生成运行时快照 | 解析失败不能改变当前有效配置 |
| inbound | 认证、握手，产生 TCP 流或 UDP 数据报 | 不自行选出站；头部、连接数与握手时间有上限 |
| router | 根据元信息和规则顺序选择策略 | 结果包含命中规则和可脱敏的解释 |
| outbound | 直连与代理拨号 | 复用统一超时、取消及 TLS 策略 |
| resolver | bootstrap、解析策略、缓存与 DNS 请求转发 | 明确指定解析路径，防止递归拨号 |
| runtime | 生命周期、会话追踪、配置代际与资源限制 | 持有和释放资源的责任明确 |
| platform | macOS 接口、路由、DNS、系统权限 | 平台逻辑不渗入规则及协议实现 |
| observability | 指标、结构化日志、诊断导出 | 默认脱敏、采样和限额 |

数据路径：入站解析目标 → 建立连接元信息 → 规则匹配 → 策略选择 → 出站连接 → 双向转发 → 会话回收。只有规则需要 IP 而当前仅有域名时才触发对应解析，保留原始域名。

## 2. 契约先于接口数量

TCP 与 UDP 使用不同契约，保留数据报目标、源地址和会话边界。基础上下文包括目标域名 / IP、端口、入站、网络类型、截止时间、连接 ID 和配置代际。进程信息是可缺省的能力，不能假定所有平台都能取得。

TCP 转发处理半关闭、短写、背压与错误传播；取消时关闭相关资源。UDP 明确最大数据报、会话并发、空闲超时、回包关联和 MTU 行为。连接池与缓存都有容量与淘汰策略。

## 3. 配置与热重载

原生配置带 schema_version。先定义最小 schema、错误位置和样例，再确定序列化格式；YAML 为优先候选。禁止执行配置内脚本，限制文件大小、别名展开、递归层数及远端内容体积。

加载流程：读取 → 解析 → 语义与引用校验 → 准备新资源 → 提交快照。提交前发生错误时关闭新资源，保留旧快照；提交后新连接使用新快照，旧连接默认按旧快照完成。变更监听端口等无法原子切换的情况明确列为需重启项，不承诺所有字段都能热重载。

规则按声明顺序首个匹配生效，末尾必须有显式默认动作。初版包含域名精确 / 后缀、IP CIDR 和最终动作。域名大小写、国际化域名、IPv6、缺失元信息与 REJECT 行为在 schema 中写明并测试。

## 4. DNS

v0.1 显式代理阶段允许系统解析器，但必须说明域名可能由本机系统解析或交由远端解析。v0.2 引入独立 DNS 策略后才声称提供受控解析路径。

分开处理代理节点域名的 bootstrap 解析、用户目标域名解析、规则求值解析及健康检查。禁止“解析代理域名需要代理，而代理拨号又需要该解析”的依赖环。

v0.2 先实现可观测的真实 IP 模式；fake-IP 单独决策，要求映射回收、持久化选择、重载和 IPv6 测试。缓存遵守 TTL 并设上限；负缓存、过期数据与失败回退需显式策略。加密 DNS 的 bootstrap、证书校验和重试同样纳入规则，不能悄悄退回系统解析器。

## 5. macOS 接入

第一阶段以普通用户权限运行本地显式代理。修改系统代理作为单独操作，需记录并恢复原设置。

TUN 在 M0 同时调查两个候选：原生虚拟接口配合最小权限 helper；或 Network Extension。两条路线分别记录所需权限、签名、分发限制、升级和恢复方式。M3 选择一种正式路径，避免同时维护两套生产实现。

Network Extension 的 entitlement 和打包方式会影响分发。Apple TN3134 对 macOS packet tunnel 的 app extension / system extension 部署有区分，不能只凭开发机启动成功就宣称可以分发。先完成符合目标分发渠道的原型验证。[Apple 部署要求](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment)；[entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.networking.networkextension)。

原生 TUN 路线另行验证所需 TCP/IP 栈的维护状态、许可证与 IPv6 / UDP 支持。避免自行从零实现用户态 TCP/IP 栈。代理服务器地址和 bootstrap 流量的出站路径必须避免被重新导入隧道。

停止、启动失败、崩溃和重启分别设计恢复路径。退出回调不能覆盖 SIGKILL、掉电等情况，需状态日志与下一次启动时的 reconcile；只恢复本实例拥有且仍可确认归属的修改，避免覆盖用户随后更改的网络状态。

## 6. 控制面与依赖

控制面优先 Unix socket；启用 HTTP 管理接口时默认仅 loopback，要求认证，限制请求体、超时与并发。探活、读取状态和修改配置分开授权。非本地访问必须显式启用。

依赖清单记录版本、来源、许可证、维护状态与使用目的。优先标准库与少量直接依赖，锁定可复现版本。协议实现、规则资源和订阅解析分别审查；第三方代码不能通过改名消除来源与许可证义务。
