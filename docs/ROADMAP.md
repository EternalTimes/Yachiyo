# 路线图与首批任务

状态：初稿；更新于 2026-10-31。以下按依赖与验收安排，不是固定发布日期。投入量是单人配合 AI、依赖可以正常获取时的初始工程估计，M0 后重新评估。

## 1. 里程碑

| 阶段 | 交付 | 完成门槛 | 初始投入估计 |
| --- | --- | --- | --- |
| M0：选型与风险验证 | 语言决策、最小转发原型、依赖许可清单、macOS 接入调查 | ADR-001 接受；本机完成转发与资源基线；TUN 两候选有权限 / 分发 / 恢复证据；决定最低 OS，确认依赖与已选 AGPL-3.0-only 的组合兼容性 | 3–7 个有效工作日 |
| M1：v0.1-alpha | CLI、最小配置、HTTP CONNECT / SOCKS5 TCP 入站、DIRECT / REJECT / SOCKS5 TCP 出站、顺序规则 | 本地端到端、IPv4 / IPv6 声明范围、超时 / 半关闭 / 拒绝和错误配置测试通过；退出后资源回收 | 1–2 周 |
| M2：v0.1 | Trojan TCP、选择策略、有限健康检查、状态与诊断、配置快照重载 | 与独立 Trojan 服务端互通；配置失败保留旧状态；8 小时可重复负载记录无持续无界增长；日常显式代理可用 | 1–2 周 |
| M3：v0.2 | UDP、独立 DNS、macOS TUN、恢复入口 | UDP / DNS 先独立通过；实机通过路由、DNS、休眠、网络切换、强退恢复；连续 24 小时负载及日常验收 | 3–5 周，选型不确定性最大 |
| M4：v0.3 | 配置兼容子集、订阅 / 规则更新、按需求增加协议 | 字段矩阵明确；不支持项可定位；更新失败不破坏旧状态；新增协议各有互通与资源证据 | 2–4 周，按协议逐项估计 |
| M5：v0.4 候选 | 性能优化、更多平台、控制 API / GUI 接口、自动策略实验 | 每项独立立项，先解决已测瓶颈；新增平台有实际运行证据 | M3 后评估 |

粗略工作量约 8–14 周到 v0.3；签名、协议依赖和 TUN 风险可能使周期延长。串行合并各阶段上界约为 15 周，日历周期还取决于实际投入。版本是否交付以门槛为准。

## 2. 首版可用的定义

使用虚构示例配置可以完成配置校验、前台启动、状态查看与正常停止；真实节点通过本地私有配置提供。浏览器通过显式代理按域名 / CIDR 选择 DIRECT、REJECT 或远端出站。错误可以定位，密码不会进入日志，退出后不遗留监听和活跃任务。

v0.1 的“可用”限定为已测试的 TCP 显式代理场景；TUN、UDP、全局 DNS 接管和完整 Mihomo YAML 兼容属于后续里程碑。

## 4. 质量与性能验收

基准固定三组：空闲；200 条空闲 / 低流量 TCP 连接；200 条活动连接及可重复流量。另测短连接风暴与反复重载。记录客户端和服务端配置、连接建立速率、带宽、日志等级、采样周期、RSS 峰值及回落趋势，不能只报单点内存。

M2 的 8 小时与 M3 的 24 小时属于初始稳定性门槛，不等于生产级可靠性证明。M0 定义容忍范围：内存、任务数与文件描述符在预热后应围绕负载波动，结束后回落到可解释范围；发现稳定增长必须定位，不能靠重启掩盖。

性能硬指标在有基线后填写：200 连接 RSS 上限、吞吐损失、p95 延迟增量、重载耗时、恢复时限。没有基线时保留空缺，不能把愿望写成实测。

## 5. 主要风险与调整条件

| 风险 | 提前验证 | 影响与处理 |
| --- | --- | --- |
| macOS TUN 权限 / 分发不成立 | M0 原型和官方要求核查 | 延后 v0.2，先稳定显式代理 |
| 协议库许可不适配 | 引入前检查 | 更换依赖或调整许可证，不能先复制后补手续 |
| DNS 递归与代理回环 | DNS 策略独立集成测试 | 阻断 TUN 合入，先修正出站路径 |
| 用户时间与模型配额不足 | 每周比较可验收产出 | 缩减并行功能，保持里程碑闭环 |
| 兼容需求失控 | 固定字段及协议矩阵 | 未支持能力显式报错，按实际配置新增 |

## 6. 进度规则

任务状态使用 proposed / ready / in-progress / blocked / done。done 必须附验证记录。每周更新完成项、阻塞、下一项和范围变化；没有实际工作则如实记录。定期任务与自动化在需要时另行建立，本初稿没有启用任何定时操作。
