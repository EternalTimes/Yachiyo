# AI 协作与成本控制

状态：初稿。依据现有资源：ChatGPT Plus、MiniMax mPlan Go、Google AI Pro / Antigravity。具体模型可用性、配额、订阅权益和 API 价格在使用前查对应账户；订阅席位不等于 API 额度。

## 1. 按职责分工

| 工作 | 默认工具入口提案 | 输入与输出 |
| --- | --- | --- |
| 需求拆分、架构与风险评审 | ChatGPT / Codex 中可用且适合该任务的模型 | 需求 → 契约、ADR、验收清单 |
| 日常实现与调试 | 能访问同一代码版本的 Codex 或 Antigravity，按剩余额度选择 | 一个明确任务 → 最小改动与验证记录 |
| 文档、测试场景草拟、重复性辅助工作 | MiniMax 或当前成本合适的可用模型 | 明确边界与样例 → 可审查草稿 |
| 独立复核 | 与原作者不同的上下文或模型 | 补丁、契约、证据 → 具体问题与复现条件 |

以上是资源调度提案，不代表某模型已经被证明在该类任务中更强。DeepSeek、GLM、Kimi 等作为可选补充，先用同一小任务比较产出质量、人工修正时间和实际支出，再决定是否增加付费使用。

## 2. 单任务流程

1. 明确问题、范围、接口和验收；把不确定事实转为查证或实验任务。
2. 选择一个实现者处理一项任务。默认串行协作，避免多个工具同时写同一工作区。
3. 实现者完成代码、自检及验证记录；疑点附文件位置和复现方法。
4. 对认证、TLS、DNS、路由、并发与资源释放等高影响变更进行独立复核。没有第二工具时另开干净上下文，并明确其局限。
5. 根据证据修正后合并，更新相应文档。构建、测试及实机结果决定是否通过。

多工具协作不依赖全量聊天历史。每次交接提供任务卡、相关文档、当前提交或补丁、涉及模块、验证结果和下一步入口。不能直接访问仓库的工具只能交付建议，必须由能访问真实版本的实现者核验。

## 3. 上下文与预算

仓库文档保存长期决策，任务卡保存短期状态。每次仅提供相关文件和必要日志，避免把全仓与完整会话重复送入上下文。共享日志先脱敏；不要把真实订阅分发给多个模型用于调试。

优先使用现有订阅，达到配额后切换任务或工具。新增付费 API、自动重试或后台代理必须有支出上限。每周记录人工修正时间、任务通过率、调用开销和配额阻塞，以完成可验收任务的总成本评估工具。

AI 评审结果是候选意见，需要核对代码和契约。避免对简单改动反复调用多个模型；仅在风险、测试失败或证据矛盾时扩大评审。

## 4. 交接模板

```text
任务 / 里程碑：
目标与验收：
代码版本 / 补丁：
已完成与涉及文件：
关键契约 / ADR：
验证命令与结果：
未验证内容与原因：
遗留问题与下一步：
```
