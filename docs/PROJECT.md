# 项目原则与范围

状态：初稿；日期：2026-10-31。已确认：暂定名 Yachiyo、类似 Mihomo 的代理内核、macOS 首发，以及以 AGPL-3.0-only 保持衍生版本源码开放。其余内容为工作提案，可以通过决策记录调整。

## 1. 产品定位

Yachiyo 提供代理接入、规则分流、DNS 与连接管理能力。先服务单机 macOS 使用，再验证其他平台。内核与图形界面分开，CLI 是第一种管理入口；未来 GUI 复用同一套配置与控制接口。

优先顺序：连接正确与可恢复 → 个人日常可用 → 资源占用可解释 → 配置迁移 → 协议扩展 → 自动策略与图形界面。性能优化必须有测量结果。

## 2. 工作原则

1. 每个版本形成可独立运行的闭环，有明确入口、错误行为和退出恢复方式。
2. 原生配置保留自己的版本与语义。兼容层负责翻译，核心模块不散布第三方字段判断。
3. 未支持字段必须报错或在显式迁移模式下列出警告，不能静默忽略并宣称成功。
4. 复用成熟实现前检查维护状态、许可证、平台支持和互通测试。加密与 TLS 优先使用经过维护的库。
5. 所有后台工作有生命周期、并发上限、超时及清理责任。
6. 系统网络修改必须有前后状态记录、失败处理和恢复说明。
7. 诊断功能默认最小化采集；真实订阅、访问令牌和私钥不能进入仓库或测试夹具。
8. 配置、错误信息和文档描述实际行为，不以“完全兼容”“零泄漏”“不可识别”等无法充分验证的承诺替代证据。
9. 希望衍生版本持续开放源码。项目原创内容采用 AGPL-3.0-only，分发与远程网络交互遵守相应源码提供义务；第三方内容保留原许可，不擅自改换许可。

## 3. 平台和兼容性

| 项目 | 初稿范围 |
| --- | --- |
| macOS arm64 | 首要运行、性能和系统集成目标 |
| macOS amd64 | 候选支持；有实际运行验证后才标记支持 |
| Linux | 初期用于平台无关模块 CI；系统接入另立里程碑 |
| Windows | 先保持架构可移植；平台发行安排在 macOS 稳定后 |
| macOS 最低版本 | M0 按工具链、依赖与实机条件决定；开发机系统版本不等于最低版本 |
| Mihomo 配置 | v0.3 规划明确字段子集与差异报告，不承诺直接读取任意配置 |
| Mihomo 控制 API | 独立待决策，不从 YAML 兼容推导 API 兼容 |

## 4. 协议优先级提案

| 阶段 | 能力 | 边界 |
| --- | --- | --- |
| v0.1 | HTTP CONNECT、SOCKS5 TCP 入站；DIRECT、REJECT、SOCKS5 TCP、Trojan TCP 出站 | 建立可运行闭环；普通 HTTP 转发另列兼容项 |
| v0.2 | UDP 会话、SOCKS5 UDP、DNS、macOS TUN | UDP 与 DNS 必须先具备独立测试，再接入 TUN |
| v0.3 | Shadowsocks、VLESS + TLS / REALITY 候选 | 每项通过依赖审查、互通和资源测试后单独纳入 |
| v0.4 候选 | Hysteria2、TUIC、VMess、AnyTLS、XHTTP | 按真实节点使用需求排序，不作为一次性交付承诺 |
| 后续评估 | Snell、Tailscale、ZeroTier | 分别评估协议可实现性、许可证、控制平面及外部守护进程集成 |

VLESS / VMess 是协议能力；REALITY / TLS 属于安全与握手相关能力；XHTTP 是传输相关能力。适配器按实际协商组合声明支持矩阵，不能因支持其中一项就宣称支持全部组合。

## 5. 暂缓范围

初期暂缓移动端、内置 GUI、脚本执行、TLS 解密、全套覆写语言、任意动态插件与自动学习策略。Smart 类自动策略等有延迟、失败率、探测流量和策略切换基线后再评估；初期采用显式选择与受控健康检查。

## 6. 衡量方式

以固定硬件、OS、配置规模、连接数与吞吐负载记录 RSS、CPU、吞吐、p50 / p95 延迟、文件描述符及退出清理情况。对照 Mihomo 时固定同一流量、服务端、DNS 和日志等级，并记录两者版本。

M0/M1 先测基线，再通过决策记录设定门槛。用户此前看到的约 800 MB 内存占用是调查背景，不能直接当成所有工作负载的对照数据。
